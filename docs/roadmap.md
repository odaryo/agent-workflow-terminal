# ロードマップと進行状況

Issue はタスクの一覧 (何をやるか) を管理し、このファイルはフェーズの進行 (今どこにいて、次に何を閉じるか)
を管理する。役割を分けているので、Issue の本文や Project の Status をここへ写さない。
個々の Issue の状態は Issue の Open/Closed が正本で、ここに書くのは **フェーズ単位の状態と、
フェーズを閉じるために残っている Issue 番号** だけ。GitHub の milestone はこのフェーズの写しで、
Issue 一覧をフェーズで絞り込むためだけに使う (`scripts/wf-milestone.sh`)。P1〜P5 の milestone は今すべて
閉じている。P4 / P5 は未着手だが対象の Issue が無いためで、起票し直すときに開く。開いている milestone は、
レビュー由来の保留課題の置き場である旧 `P3 バグ改修` だけである。

フェーズの完了は「ゴールを実際に試せた」ことで判定する。Issue が全部閉じても、試して動かなければ
閉じない。逆に、Issue が残っていてもゴールが試せていれば残りは次フェーズ以降へ送る。

更新のタイミング: フェーズを閉じた時、フェーズの Issue 集合を変えた時、着手中の Issue を変えた時。
セッションの最終報告 (handoff) には書かず、ここに書く。

### App/ の UI 配線の検証手段を持った

#230 で「main では行選択が動かない」という報告が出たが、計測の結果**製品コードは壊れておらず、
エージェント側の UI 検証手順の誤り**だった (not a bug で close)。非アクティブなウィンドウへの初回
クリックはウィンドウのアクティブ化に消費されて `onTapGesture` に届かない一方、SwiftUI の Button は
同じ状況でも反応するため、「クリックは届いているのに行だけ無反応 = 実装の欠陥」と誤って結論できてしまう。

同じ罠を次のエージェントが踏み直さないよう、実機検証のハーネスを `scripts/` へ入れた (#231)。
最終バンドルを起動し、Accessibility で要素位置を取得して実 HID クリックを送り、ラベルを検証する。
上の罠はハーネス側で閉じてあり、「なぜ」はスクリプトに記録した。CLAUDE.md の
「App/ の UI 配線は動かして確認する」もこのハーネスを指すよう更新した。

この一件は、UI 層に GREEN が効かないことの実例でもある。710 tests が通り敵対的レビューで

### P2 全体レビュー (2026-09-08)

Issue が全部閉じた時点で、実地確認の前に main (6bc2186) を 6 領域 (tmux 境界 / Agent 状態モデル /
Git 境界と worktree 寿命 / Diff とコメント送信 / App 層 / ファイル閲覧と検索) に分けて敵対的レビューにかけた。
外部 CLI の主張はすべて隔離環境で計測。結果は Critical 4 / Major 17 / Minor 多数で、**現状の main では
ゴールが成立しない**と判断した。理由は3つ。

- 中核機能が現行版で動かない: Claude Code 2.1.263 は空の入力欄にサジェストを常時描くため、Ready for
  Review / Idle が一度も出ない (#217)。パーキング時の「起動直後だけ」という前提が計測で否定された
- 端末の基本動作に穴がある: タブ切替で first responder が移らず打鍵が別 worktree の Agent に届く (#233)、
  detach したタブが復帰できない (#234)、端末設定を変える手段が無い (#236)
- 設計書どおりに作った層が App から呼ばれていない: session 生成・Close・pane 操作・tmux 版数検出は
  ライブラリにあるだけで、§4.4 の history-limit も §4.2 の window-size も本番で適用されていない (#235)

上の「残る Issue」11件 (#233〜#243) を P2 に追加し、パーキングロットから #217 / #73 / #90 を引き上げた。
Close 経路の Critical (#244、detached HEAD が無警告で消える) は Close が App 未配線のため P2 に入れず、
配線前に §3.4 を確定する条件として `設計判断` を付けてパーキングロットに置いた。残り 15 件
(#245〜#259) は `P3 バグ改修` へ。

教訓として残すもの: (1) Issue が全部閉じたことと機能が使えることは一致しない — #24 / #13 は閉じているが
Close と pane 操作はユーザーから使えない。(2) 統合テストは CI で一度も走っておらず (#73)、fixture に版数が
無いため (#90) 外界のドリフトを 710 件の GREEN が検知できなかった。(3) パーキング時の影響評価が計測に
基づいていないと、#217 のように前提が誤ったまま駐車される。
